How many particles can run at 60 FPS?

Saved hardware: NVIDIA GeForce RTX 4070 Laptop GPU. 1440 × 900, device pixel ratio 1.

8,000,000 visible particles maintained about 60 FPS in every recorded run at that count, including three longer confirmation runs.

Some runs missed the target from 8,792,000 particles upward. Near the limit, browser scheduling and GPU clocks can change the result.

Every live particle is checked against the rotating D20's surfaces. Particles ignore one another. The sprites read positions directly from GPU memory. Changing camera coverage or resolution changes drawing work.

Does drawing affect the limit?

At 9,390,000 particles with drawing disabled: 59.94 FPS, 8.17 ms for the GPU collision pass. Compare the same visible count above to see the rendering cost.

Collision and sprite passes have separate GPU timestamps. Total frame time also includes the Babylon shield, browser compositing, CPU submission and display pacing. These stage times cannot simply be added to predict FPS.

Repeat the measurement

Run npm run benchmark:particles. The search increases particle count, refines the boundary and confirms it with three longer runs on each side. Each count warms up for 2 seconds; search runs last 5 seconds, confirmations 8 seconds.

At least 59 FPS and frame p95 below 25 ms (less than 1.5 refresh intervals at 60 Hz); all requested particles alive, collisions observed, no GPU errors.

Particles sweep against the rotating D20's 20 triangles and ignore one another. Five offset rays approximate each particle sweep. This is the dedicated collision demo, not an AVBD rigid-body benchmark.

This capacity applies to this surface-only particle workload. It does not describe how many colliding AVBD rigid bodies a scene can solve.
